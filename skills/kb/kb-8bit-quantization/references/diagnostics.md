# 掉点诊断：由组误差走到任务证据

## 1. 先决定要回答什么

- **格式差异**：保持算法、组轴、候选预算、中心、后端与覆盖一致，只换码本。
- **部署组合**：允许W/A规则、变换、group一起选优，但把收益称组合收益。
- **因果定位**：固定同输入、路由、batch和后端，做可解释的局部干预；先恢复层组，不默认逐层扫满。

小幅掉点先看逐题翻转与margin，再决定扩样；不要为解释一个随机均值把所有张量全部落盘。

## 2. 排除实现与协议错误

| 症状/错误 | 核查 |
|---|---|
| batch升高，分数改变 | 先区分正常BF16轨迹变化与跨样本/padding尺度污染；逐样本回放QDQ |
| 小样本与大样本doc_id同号不同题 | 先随机取N，再排序N；用doc/prompt/target三哈希匹配 |
| MoE“已量化”但效果异常 | 非标准/fused权重是否被覆盖；打包是否共享实际量化W |
| 恢复BF16层组后救回很多题 | 是否同时改变expert×sample路由顺序、shape或算子backend |
| KV8看似完全无损 | 是否只写cache，prefill仍消费未量化KV；是否正确读回 |
| SQ后浮点就变差 | Norm全部消费者、router、共享expert和权重切片补偿是否齐全 |
| 新变换仍命中旧cache | 检查真实W摘要、fit/transfer摘要、预处理、粒度和规则key |
| 进程已结束但没有数表 | 看新鲜日志/错误/原始结果，不以exit或残留状态代替验收 |

## 3. 分布统计对齐真实定标组

### 应保存的最小证据

- 组身份：模型revision、层/投影、expert、样本hash、token/head/channel/group索引、有效长度。
- 原始X/Xq或可精确重放的切片；scale、center、候选id、量化前后dtype。
- min/max、mean、population std、abs分位点、峰度/crest等按需指标。
- 最大值/q99、尾部元素占比与**信号平方能量占比**；常数/全零组单独标记。
- 饱和比例、归零比例、对应误差能量；分开near-zero、中值、峰值区间。
- 原单位MSE、NMSE、最大绝对误差、输出MSE/NMSE；NMSE分母近零时必须注明。

### 几个不能省的细节

- population std使用`correction=0`；改成样本std就改变σ规则。
- per-channel统计中一列才是一个标量scale组；把所有channel一起算NMSE会掩盖坏channel。
- MoE length应为真实路由行数，不能误取occupancy第一格的0/1。空组跳过、padding排除。
- 真正全局max取所有调用的最大值，不是“每次max的平均”。保留对应组身份。
- 短组nearest-rank q99可能等于max，因此`tail99=0`不说明没有outlier。
- 不把非均匀分段抽样称均匀reservoir；若量化损失用全体而分布图用抽样，明确区分。
- 统计脚本也可能出错；以少量保存X/Xq用CPU FP64、独立分位数和`math.fsum`复算关键数字。

## 4. “看着不好量化”的信号如何使用

| 信号 | 可提出的假设 | 不能直接推出 |
|---|---|---|
| 同组max/q99很大 | Amax可能让主体落入低分辨率区 | 尾部一定该裁剪、HIF8一定胜 |
| 少数值占大部分平方能量 | 峰值舍入可能决定误差 | 大幅值就是唯一任务因果 |
| 大量subnormal/归零 | 可能发生主体损失 | 每个小值都重要、一定掉点 |
| W直方图像钟形 | 可试对称中心、便宜RTN | 各行高斯、W必然比A好量化 |
| 局部MSE下降 | 这个代理目标改善 | 全模型能力改善 |
| 某层恢复救回题 | 该干预改变了答案 | 原错误唯一来自该层 |

没有跨模型通用的`max/q99`或NMSE合格阈值。阈值只适用于明确的原语/配方/误差预算。

## 5. 本地反例：记住为什么不能只看直方图

### 极端概率行不一定危险，错误scale反而伤峰值

GLM layer46/head8/query3872：P max/q99约136510，约99.51%的非零概率落在E4M3 subnormal区。

- E4M3 Amax的P-only PV NMSE约1.11e−6；HiF8 Amax约8.55e−6。
- 共享q99规则把0.9609375峰值舍入为1.09375，P和约1.13347，PV NMSE约0.018496；没有补做归一化。
- 因此“绝大多数码点很小/很粗”不等于输出风险；关键峰值的还原更重要。也不能据此宣布所有近零误差可忽略。

### 主体KL丢掉的是能量，不只是离群点

同一极端行，μ±10σ窗口包含99.9742%元素，却丢掉99.9301%平方能量。51个scale的主体KL全部为0，但PV NMSE横跨2.676e−6～0.022688。

- KL并列时默认3σ不是学到的最优规律。
- “覆盖更多σ”只说明包含范围；不说明还原精度，也不说明分布高斯。

### 真定标组里，峰值误差集中但仍不是逐题因果

独立复算720个原始组、完整114个诊断batch后：最坏NMSE为普通Linear0.00360492、路由expert0.00342265、K0.00690195、V0.00118206。

- layer18/head13/token0的K：−4.34375→−4.75、1.875→1.953125；两峰占88.05%信号能量、97.54%量化误差，未饱和。
- layer22 shared-down/channel1063，107有效行：85→88.5、80→80.5；两峰占99.9474%信号能量、96.1678%误差。MSE0.121478却NMSE约0.00095349。
- 8个退步/救回/正确对照案例最坏K NMSE重叠0.00616～0.00678；单个局部指标没分开对错。
- 早期“expert最大2.11%”因length/归约/映射错误已撤销，不得复用。

## 6. 层/block恢复的正确用法

1. 取BF16对、量化错的题，再配同任务正确对照；记录选择偏差。
2. 固定诊断batch后重新跑BF16与quant参考。历史退步题可能因分批变化不再退步。
3. 先按连续层组恢复W/A/KV；保持路由顺序、GMM backend、shape、输入与模板一致。
4. 报告稳定退步的救回、稳定正确的损害，以及**所有quant原正确题**的新错误。
5. 如果多个组都能救同一题，不能定位成唯一坏层。局部输出误差与完整答案干预分开。
6. 只在能改变下一步策略时，再拆W-only/A-only/KV或追踪单组反事实。

本地47层分8组、114题诊断：57个历史退步只有31个在新诊断batch稳定；22/31被至少一组救回，只有5个是单组独有。恢复18–23层将64/114正确提高至79/114，救回12/31，同时伤害4个quant原正确题。W-only干预是14得12失、净+2，不是无副作用补偿。

## 7. 如何结束诊断

- 能指出实现根因：修共享根因，重新做受影响的最小验收。
- 只证实局部误差：标为机制线索；不把它写成已证实的任务掉点原因。
- 多组均能改变答案、区间重叠：接受阴性/不确定结果，回整体配方研究。
- 达到研发目标：冻结配方、保留证据。正式部署/论文结论另做未参与选参的确认。
