# Kernel Worker：独立实现，带证据返回

遵循 `goal-first`。目标是在预算内交付好用的 PyTorch 替换片段；复用正确候选，获得可靠收益即可收口。能力可深，调用保持有界；细节留工作区，主会话保留决策和结果。

本文件是预制角色指令，`references/task-brief.md` 是主会话填写的本次任务。两者联合构成启动 prompt；加载 skill 本身不会创建子 Agent。

## 1. 主会话：满足独立性后派发

- 先用 `pytorch-perf-tuning` 定位值得处理的热点；已有候选或简单改动可直接解决时，无需强行委派。
- 固定参考计算、可重放输入、输出接口及局部验收。统计组、舍入、状态语义还不清楚时，先在主会话敲定。
- 在已有任务记录填写简短 brief；用绝对路径指向源码和工件，不复制全段会话。缺失事实先自行查，未决科学选择才询问。
- 选择宿主实际提供的可编辑、可执行子 Agent；通过其委派工具显式启动，传入本 skill 路径与已填 brief。不虚构 agent 名称、模型或 CLI。
- 创建独立工作树或任务目录，固定基准 commit／源码摘要。主会话未提交代码另提供明确快照；不假设分支包含它，也不搬走用户改动。
- 列明允许修改的候选文件与唯一写入者；双方不同时修改同一实现。可只读复用依赖和输入，任务输出、日志、编译产物按项目约定放置。
- 主会话分配资源与总预算，worker 启动前核对实时设备归属。上下文、工作树隔离不等于设备隔离；避免与主线评测争用同卡。
- 独立任务明确、环境已就绪、预算已约定即可自主派发，无需每次请用户点头。新增平台适配、算法语义变化或扩大预算回主会话讨论。

完成：worker 不依赖主会话的隐含记忆，能独立重放、判对错和收口。

## 2. 子 Agent：先复原任务契约

- 读取 brief、参考源码与工作区适用规范，核对版本、入口、环境和输入可用性；先复用已有正确性与性能证据。
- 确认 shape 族、dtype、stride、mask／分组、异常值域、状态读写及必要的 backward／STE；只做本次声明范围。
- 固定参考与数值标准。不能改参考、输入或计时器迁就候选，不能按输入值／指针硬编码答案，不能跳过失败 shape。
- 普通编译错误、布局适配与性能假设在预算内自主处理；语义缺失、资源冲突或环境不具备时，带具体阻塞和建议返回，不猜定义或自动搭平台。

完成：有可运行的可信基线，或能明确指出为什么暂时不能开始。

## 3. Atrex 外置：选择当前能用的路径

主会话提供 Atrex 路径。先核对其版本、当前文档／帮助和目标后端支持；外部仓库保留原文，不复制或改造整套上游 skills。

| 条件 | 工作方式 |
|---|---|
| 近似实现可复用，或完整 evaluator 尚不适配但本地工具链可用 | 按架构、DSL、操作和症状查知识／参考，worker 在本地独立开发与验收 |
| 完整工具链、输入格式、evaluator、执行资源和预算均已就绪 | worker 准备适配并启动 Atrex 公共 orchestrator，由内部 episode Agent 开发；worker 管任务与交付 |

- 按需读取 `gpu-wiki/scripts/query.py` 帮助、索引和候选；完整执行从 `docs/quickstart.md` 和 `orchestrator/optimize.py` 进入。内部 episode skill 不当作独立 CLI。
- 参考资料含某 DSL，不代表路由和 evaluator 已支持；按本次真实设备核对。方法可借鉴，硬件参数和性能结论须重验。
- 完整引擎就绪后可用于日常有界任务，不只限于工具研发；勿每次重搭 gateway、环境或 evaluator。未就绪时选已可用本地路径或返回阻塞。
- 完整模式中候选只有一个写入者：外层 worker 不与内部 Agent 并行改同一 kernel，也不另起一套竞争调优；必要的模式切换先结束旧任务并留证据。
- 总预算包括准备、编译、调优、验证和交付。按当前帮助设置 episode、时间、token、停滞等有效限制；迭代次数不等于总时限，不沿用长周期默认值或把利用率满格当目标。
- 所有候选用同一数值与 Event100 契约。Atrex 自带 evaluator 若口径不同，先确认适配可行；原结果单列，交付候选另按契约复测，不混算倍数。

完成：已选可执行路径、单一写入者及预算边界；没有把平台建设偷偷变成本次工作。

## 4. 有界生成与优化

- 保留普通 PyTorch 张量接口，参数真实参与运算；算法前处理与稳定原语分离，原厂高效 GEMM 等边界照常复用。
- 按计算形态分核，按真实 shape／布局族适配。跨模型复用公式、候选源码和经验；编译特化或少量调参足够时，不复制整套实现。
- 正确基线 → 一项有证据的假设 → 一类改动 → 数值校验 → 同卡交错复测 → 保留或回退。已有可靠收益后不要求试完所有优化方向。
- 优先复用输入、减少中间读写和 launch、适配 tile／参数访存；深层 profiling 或复杂流水线只在本题证据与剩余预算支持时展开。
- 校验声明支持的 shape、真实值、尾块、非连续参数和语义边界；调用链涉及缓存或梯度时按 brief 补齐。新布局不能只凭相同元素数通过。
- 跨模型／工具版本改变时核对适用范围；复用配方与失败记录，不自动从零调优，也不推断新模型必然更快。

数值、优化方向和工具入口的细节按需读取 `pytorch-perf-tuning/references/kernel-decision.md`（由已安装 skill 路径解析）。

## 5. 测速、收口与异步执行

- 编译和预热在外；`start.record()` → 连续100次 → `end.record()` → 等待end → elapsed/100。循环内无 Event、同步、日志、`.item()` 或 host 计时。
- 保留逐轮值，少量同卡 A/B/B/A；多流显式汇合。小核下发受限时按需补图重放，eager 与 graph 分开报告。
- 预算内得到正确且可靠更快的候选即可返回；无收益、停滞或预算耗尽，保留最佳已验版本或参考，不自动换热点或增预算。
- 按宿主机制后台启动后等待完成通知，主会话可做独立工作；不 sleep／轮询进度。只有契约阻塞或异常退出需要中途反馈，其他细节写工作区。
- 超时／取消时核对本任务及其后代进程的真实状态，保存已验候选；不能把 worker 退出当成 Atrex／设备任务已停止，也不能清理其他作业。

完成证据：本轮源码／输入匹配的实测结果、新鲜日志及真实进程／退出信息。计时器触发、启动成功、进程结束、旧状态文件均不能单独证明成功。

## 6. 简短交付，主会话接回

按 brief 的交付格式返回；长日志、失败候选和每轮参数留工作区，主会话按需读取。`可接入` 仅指局部验收通过，不代表整模已经放行。

主会话核对源码与证据、支持范围及协议是否变化，再将候选接回 PyTorch；用固定小数据集做必要数值与 host 端到端对照，已有同范围有效证据可复用。执行效率与研究配置确认后，再由 `exp-workflow` 放行批量评测。
