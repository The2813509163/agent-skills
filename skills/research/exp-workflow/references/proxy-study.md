# 预研对象：张量回放、小数据集与探索矩阵

## 先问：什么观察能改变下一步

先选证据路线，再设计代理。机制或局部误差问题适合代理；未知参数响应、方案权衡、消融／交互和论文覆盖可直接用实验矩阵。代理不是所有整模研究的前置条件，也不天然比矩阵更有说服力。

选择代理时，明确它要排除的解释，并保留关键依赖；不能先收一批张量，再想它们能研究什么。选择矩阵时，按整体说明认识目标、因素／范围、指标和预算，不必预言每个格子。

Agent 提案的说法可以是：

> 我建议从真实校准运行中按条件 C 选出对象 X，连同依赖 Y 一起回放；用 A/B 对照看指标 M，预计花费 B。若观察到 R 就关闭这条分支，否则进入小整模验证。它看不到 Z，因此整模阶段要专门检查 Z。你是否认可研究目标、选择规则和这个取舍？

用户不必发明这个方案。对未知的研究意图给推荐、问原因；可查的数据来源、接口和粗略成本由 Agent 调查。

## 按假设选主体

| 问题 | 研究对象／证据路线 | 必须保留／不能推出什么 |
|---|---|---|
| 参数响应未知、多目标权衡、消融／交互 | 有界探索矩阵；正式主张用相应验证矩阵 | 可直接测真实整模；先通过代码就绪检查，保留基线与必要范围，不只展示胜出点 |
| 数值格式、尺度、平滑／局部变换 | 真实激活 X、准确配对的 W 与参考输出 | 原计算分组、dtype、bias／补偿；不能直接推出任务分数 |
| QK／softmax／PV 或 mask 处理 | Q/K/V、mask、位置与必要的缓存片段 | 真实查询行和归一化；不能只看张量重建误差 |
| MoE 专家计算／共享分支补偿 | 真实路由、门控权重、专家输入与合并输出 | 稀疏频次及共享路径；固定路由不能证明变换后的路由正确 |
| 层间误差或重复变换累积 | 短层组、连续多步回放 | 输入必须承接上一步输出；独立层回放看不到传播 |
| KV 写入／读出、位置与生成状态 | 同一短序列的 prefill＋少量 decode | 检查缓存实际被读取、历史前缀及位置；只测 prefill 不够 |
| 训练／更新规则 | 固定小批次的 loss、梯度和少量更新 | 保留优化器状态与随机性；短轨迹不证明最终收敛 |
| 强全局反馈、无法有效隔离 | 极小真实整模、固定少量样本 | 明确仍是预研，不将分数分辨率当统计把握 |

简单合成输入适合边界／机制检查；代表性结论优先真实对象。缩小规模时说明损失的依赖，尤其长上下文、稀有路由和动态统计。

## 小数据集＋小矩阵：直接观察评测表现

不必抽取张量：保留真实模型和评测入口，固定一个代表性小子集，扫描参数或做小矩阵消融，本身就是务实的预研。

1. **固定子集**：按问题随机或分层选样，固定身份／顺序／种子；候选使用同题。样本数、参数配置数、执行 batch 分别说明，不把缩数据等同改 batch 或缩序列。
2. **设计小矩阵**：选择参考配置与有解释力的参数范围，明确要看的分数、吞吐或权衡；不强制每格预言结果。
3. **先审视执行路径**：真实评测代码将被批量复用，先用 `pytorch-perf-tuning` 清理明显浪费、校验同算法实现和短路径耗时；已验过的代码／公共核复用证据，无须逐格重新优化。
4. **按整批估成本**：共用加载＋各配置准备／编译／评分＋必要重复；检查能否合法复用加载、tokenize 或统计。参数改变后恢复必要状态，响应缓存不能跨不同算法配置误用。
5. **看配对变化与局限**：小样本可看趋势、消融和下一步方向；不能把分数分辨率当统计把握。需要时补独立子集或必要重复，不默认扩成全量。

Agent 可以这样提案：选固定小子集，在同一实际评测入口比较参数候选与基线，先做一次代码就绪检查，再跑整批；根据响应趋势决定细化范围、扩大确认或关闭分支。预研的形式和步骤顺序随问题调整，代码优化按执行方式与整批成本触发。

## 激活＋权重：可复用的采集与回放方法

1. **固定来源**：checkpoint、训练／校准 split、采样种子和顺序；避免用最终评测集挑案例或调规则。
2. **先定义选择条件**：来自假设的格式／候选无关统计，或用户指定条件；写清统计轴和实际定标组。
3. **小扫描与分层取样**：普通对照＋符合条件的对象；若关注低频极端，记录扫描分母和命中频次，不按谁获胜来筛选。
4. **采集最小依赖闭包**：X 与正确配对的 W，必要的 bias、mask、位置、路由、补偿、尺度和状态；不要只凭维度相等认定矩阵配对。
5. **保存回放身份**：样本身份／内容摘要、模块／层／专家、形状、dtype、stride、采集前处理、源码／配置摘要。
6. **先验回放**：未改算法时，离线回放应复现在线参考输出；不一致先查遗漏的 cast、mask、共享分支或状态。
7. **候选配对研究**：同一对象固定其余变量；保存逐对象结果，记录普通回退、尾部与最坏组，不只报一个聚合均值。

- 实体张量按项目目录约定保存；共享权重可引用不可变 checkpoint＋模块名及摘要，不必重复落盘。记录格式必须能取回完全配对的值。
- 避免 hook 持有计算图／设备张量：采集结束移除 hook；只保存研究需要的范围。需要梯度的研究另保留可重建梯度路径。
- mask 无效位置不作为离群值或有效样本；稀少路由专家不能只因命中少就被排除。
- 搜索／选参对象与确认对象分开；已有采集库可复用，但需核对当前前处理和采样分布是否适用。
- 代理变换会改变后续激活、路由或缓存时，旧输入只代表固定输入局部效果；用短链或小整模补这个盲区。

## 指标从实际计算目标推出

- 重建误差是辅助；优先观察实际输出，如 `XW`、QK／PV、残差合并、logits、loss 或梯度。
- 明确原单位误差与归一化误差的汇总方法；矩阵平均之外检查实际 token／query／group，避免聚合掩盖少量严重退步。
- 必须有普通样本护栏；极端样本上的好处不能掩盖常见输入的稳定退步。
- 用参考输出逐组挑最优参数得到的是已测候选 oracle；若要上线共享规则，需另行形成规则并在确认对象上验，不把 oracle 冒充实际收益。
- 代理排名与整模指标的对应关系仍需验证；小样本整模也只支持所声明范围的结论。

## 简短方案：讨论后只保留一份

写在现有任务卡／实验记录；确认前可以直接在对话中给表，确认后将必要配置与运行记录一起保存。

| 字段 | 要回答的问题 |
|---|---|
| 假设与下一步决策 | 什么结果会继续、关闭或改变分支？ |
| 代理主体与来源 | 哪个 checkpoint／split／模块／状态？已有对象能否复用？ |
| 选择与代表性 | 条件、统计组、普通护栏、扫描频次，如何避免候选胜负偏差？ |
| 对照与指标 | 只改变什么？参考是什么？看实际哪个输出，容差如何定义？ |
| 成本与止损 | 少量对象／候选及预期时间／内存；何时停止扩展？ |
| 盲区与整模桥接 | 没有覆盖什么？用哪种最小整模检查补上？ |
| 执行与记录 | 用户已确认哪些选择、允许哪些运行；入口、工件与判定在哪里？ |

研究有界即可，不强制统一样本数或误差阈值。已确认且结论明确就执行，不把讨论变成反复填表。

## 转向整模前的三个问题

1. 现有证据或局限是否说明下一轮的价值：区分解释、认识参数／权衡、补充消融或验证论文主张？没有有效代理时，矩阵本身可承担认识任务。
2. 候选的在线实现是否仍表达同一个算法，且已按 `pytorch-perf-tuning` 完成必要审视、校验和短实测？
3. 耗时整模要回答什么问题、支持哪些主张或前沿曲线，范围、预算和评分口径是否已确认？

有问题未答就补最小证据；问题已答就进入已授权步骤，避免代理预研和性能优化各自无限延长。
