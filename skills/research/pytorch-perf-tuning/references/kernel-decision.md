# 按模型 shape 生成、复用与迭代融合核

## 定位：服务 PyTorch 算法原型，默认轻量使用

算法开发继续留在 PyTorch；用 kernel 替换常用、可与算法解耦的操作，减少等评测的时间。这里不建设 vLLM／SGLang／TensorRT 式部署引擎，也不追求 FlashAttention 式极限训练优化。衡量的是研究迭代更快，不是峰值性能排名。

| 工作 | 投入方式 | 收口 |
|---|---|---|
| 日常算法任务使用工具（默认） | 复用候选与经验；给短预算，少量形态适配和优化 | 正确、收益可重复，或预算耗尽；保存可用版本，回算法主线 |
| 独立工具建设任务 | 可专人系统研究识别热点、生成核、优化方向、校验器和 Atrex 适配 | 经验沉淀成易用配方，降低后续使用成本；不把研发流程强加给每次使用 |

1.25× 的可靠收益已经可以很好；不要为追到 1.3× 付出大量额外工作。这是投入取舍示例，不是最低收益门槛或加速上限。允许 Agent 写复杂核，和每次调用都深入调优，是两回事。

## 优化对象：真实调用片段 × shape 族 × 设备

Agent 可以为不同模型生成一批专用核，并借鉴已有模型的实现。不要求全模型通用，也不因手写工作量就否定方向；日常优先最小适配，预计超出短预算的探索留给独立工具任务。

不同模型常共享计算公式，主要差别是 hidden size、head dim、长度、batch、专家分布；还要核对 dtype、stride、mask 和归约轴，不能只看总元素数。跨模型共享公式与经验，具体实现、分块和调度允许特化；同一源码的编译特化或少量调参已够用时，无需复制整份代码。

### 从真实模型到候选核

1. **采集工作负载**：短跑真实任务，记录模块与连续操作、shape、dtype、stride、分组／mask、调用次数和耗时；保存代表性输入或确定性的回放方法。采集不混入正式测速。
2. **划定片段**：例如 cast→中心／尺度变换→截断／舍入→还原，或 mask→归约→归一化。一个语义连贯片段尝试一个 Triton／TileLang 核；不同计算形态分别实现，需要全局归约或保留库边界时拆核。
3. **按 shape 族特化**：区分大／小输入、prefill／decode、固定通道宽与变长 token 数、稀疏专家负载。允许不同 tile、向量化、归约和流水线；用实测选择简单分派，不先造通用注册框架。
4. **有限尝试**：最相近的正确实现作起点，从下表挑相关方向，各先试少数候选；固定参考和输入，每轮只改一类因素。换模型先回放新 shape 与真实值，通过则沿用，不默认从头爬坡。
5. **验收并收口**：检查拟交付候选在声明支持的工作负载上是否退步，再做固定小数据集 host 对照；收益明确就结束本轮。正确性不通过则修复或回退，不能为节省时间放宽标准。

- 固定 hidden size 等维度可编译特化；频繁变化的 token 数可用运行时长度、mask 或少量长度桶，避免每个长度都重新编译。分桶不得改变 padding 统计和样本独立性。
- 只按 shape／布局／设备选择实现；参数值和输入必须真实参与计算，不把校验输入或输出硬编码进核。
- 为已观测高频 shape 做候选，同时验证尾块及覆盖边界；未支持的形态显式走参考或报错。不要为假想模型穷举所有 shape，也不要为复用强迫不同模型采用同一份最优实现。
- 分列编译、预热与稳态成本；一个专用核是否值得保留，由实际调用量和整模收益决定。

### 常见方向：按症状取用，不是必跑矩阵

| 观察 | 首个低成本尝试 |
|---|---|
| 高频连续小操作、多次 launch | 融合一个稳定片段，减少中间张量和下发 |
| 同一输入被反复 cast／读写／转置 | 核内复用中间值，按实际 stride 访存 |
| tile 太小或片上容量不足 | 试少量邻近 tile；按形态独立配置 |
| 广播或专家参数先展开成大张量 | 在核内按行／通道／group 读取参数 |
| 归约／同步成本突出 | 复用现成归约或做简单分阶段处理，保留统计定义 |
| 固定通道宽但 token 数频繁变化 | 特化稳定维度、运行时处理长度，减少重复编译 |

每轮只挑当前证据支持的方向；已有候选获益后不要求试完表格。复杂流水线、ISA 深挖、跨 DSL 大搜索归工具建设，除非本轮任务本来就在解决该问题。

### Atrex 是外部知识与优化工作流

本 skill 负责选热点、采集工作负载、接回 PyTorch 和验收。任务可独立重放、接口与预算明确时，通过 `kernel-worker` 委派到独立上下文／工作区；主会话提供已填 brief，worker 处理实现细节并带证据返回。

日常可借用知识快速适配，也可在环境／evaluator 已就绪时有界调用完整 Atrex；不把完整能力限定为长期研发。新平台适配与工具建设另设任务，不让每次使用重做准备。

| 需要 | Atrex 仓库内入口 |
|---|---|
| 架构机制、DSL 和同类核经验 | `gpu-wiki/scripts/query.py`，按设备架构、vendor、DSL、operator 过滤；先看当前帮助及索引 |
| 可借鉴源码 | `gpu-wiki/reference-kernels/`、`reference-projects/`；核对来源及使用约定 |
| 已就绪的有界完整任务，或独立工具研发 | `docs/quickstart.md` → 唯一公共入口 `orchestrator/optimize.py` |
| 完整任务内的证据循环 | `skills/gpu-kernel-episode-loop/SKILL.md`；它由 orchestrator 的 episode 上下文使用，不是独立 CLI |

选择 DSL 前核对目标设备编译器、Atrex 当前框架路由及 evaluator。存在 Triton／TileLang 参考资料不等于完整任务已支持该后端；知识与方法可先用于本地独立探针。外部资料沿用原仓，不复制其整套 skills、调度器和知识库；项目只保留适配与证据。

- Atrex 路径、revision、真实输入与数值／Event100 契约由任务提供；本 skill 不写死服务器路径。上游 evaluator 的口径须核对，交付候选按任务契约复验。
- 完整引擎已含内部 Agent：外层 worker 负责适配与交付，避免两层并行编辑同一候选。准备、编译、迭代、验证均计入总预算，不直接沿用上游长周期默认值。
- 子任务细节留工作区；主会话核对支持范围与证据，再做必要的 PyTorch 调用链／小数据集 host 验收。局部核通过不自动放行整模。

## 研发阶段也可以复用 kernel

先划分变化范围：离线权重变换、校准和选参可以频繁变化；在线 cast、归一化、舍入、还原等模式可能一直相同。把参数作为输入传给小核，不必把整个算法固化进去。

新量化格式没有硬件支持，也能用 BF16/FP16/FP32 实现融合伪量化。输出仍是普通浮点张量，随后调用原厂 GEMM；不必重写 GEMM，也没有原生低位矩阵乘红利。

| 路径 | 真正改变的部分 | 验证重点 |
|---|---|---|
| 编译器融合 | 自动融合 PyTorch 表达式 | graph break、数值和稳态收益 |
| 单独的逐元素融合核 | 中间量留在寄存器/片上，减少全局读写与下发 | 舍入、cast、tail、广播 |
| 动态统计 + 融合核 | 归约单独或合并 | 原有统计组和 mask；不能把全局 scale 偷换成每 tile scale |
| 融合核 + 库 GEMM | 保留矩阵乘，只改输入准备 | 完整片段是否加速 |
| 直接融合进 GEMM | 自管 tiling、流水线、矩阵乘 | 成本更高；先与上一行比较 |

不能从 `逐元素 FLOP / GEMM FLOP` 推断时间。逐元素算子可能受下发、HBM、Vector 指令影响，GEMM 则走另一条高吞吐执行路径。

## 轻量爬坡：采用 Atrex 的证据循环

方法来源：Atrex Kernel Agent，核对版本 `5f6709d8cec7d6c3690c7831f72ddae1532e7b09`（2026-10-19）。入口是仓库的 `skills/gpu-kernel-episode-loop/SKILL.md`、`long_horizon/verifier.py`、架构过滤的 `gpu-wiki/`。

1. **锁基线**：参考计算、输入、dtype、分组、计时程序保持固定；保存一个正确的融合版本。
2. **一个假设**：例如 tile 太小、重复读写、归约同步、昂贵指令。Event 给时延，源码给假设；没有计数器不能宣称测到了带宽瓶颈。
3. **一种改动**：从相关方向选一个低成本候选；不要求按 tile→访存→指令→流水线全部走完，也不同时改公式和计时方式。
4. **正确性先行**：失败版本不参与“更快”的排名；记录失败原因，不修改参考来迁就候选。
5. **同卡交错复测**：A/B/B/A，每段内部仍是首尾一对 Event 包住 100 次；多候选可 A/B/C/C/B/A。编译与预热在外。
6. **保留或回退**：全工作负载看退步；小幅差异看重复波动，不只挑赢家的一次。保存源码摘要、每轮值、假设和结论。
7. **回接调用链**：原链与拟交付核接同一后续计算；需要解释爬坡时才加初版对照。核快而整段不快，可在剩余预算内查一次下发／图执行；否则记录结论并回主线。

这套方法可以直接 Bash + Python 执行。无需为单算子探针搭 supervisor、gateway、systemd 或多 Agent 系统。使用完整 Atrex 时遵守它的运行约定；其当时的 Ascend 支持仍需另备 NPU evaluator，不能直接当作本机开箱即用框架。

## Event 测量的两种口径

- **普通调用**：start → Python 循环 100 次 → end；不加循环内标记、同步、取值。包含设备在两标记间的空闲。
- **图执行对照**：预先捕获 100 次相同计算，start → replay → end，时间再除以 100。减少 Python 逐次下发空隙；图构建不计时。
- 两组内部各自比较。图数据不是 eager 的实得收益；重复同输入是热缓存、固定形状微基准，不代表真实整模。
- 多轮保留原值。多流需要正确汇合；缺少依赖的计时可能提前结束。
- 小核必须留意 Python 供给：只有几微秒的 kernel，普通 Event100 仍可能测出百微秒级摊销时间。

## 正确性：参考语义，而不是“差不多”

- 列清 rounding、饱和、subnormal、零、异常值、统计轴、padding、dtype 转换顺序；不要默认 ties-to-even。不同格式、项目可能用 half-away。
- 同 scale 的 QDQ 尽量逐值相等；改写归约或 GEMM 时按事先约定的容差，不能随结果放宽。
- BF16/FP16 可穷举全部有限位模式，再配几组非二次幂 scale；FP32 检查码点中点及 `nextafter` 两侧。
- 测奇数长度、tile 边界两侧、多块、非零 storage offset；只支持 contiguous 的原型要明确，接入时不支持的布局走参考。
- 不只看输入 stride，也检查 scale/center。无归约的退化组可能直接把非连续输入视图当均值；一维步进切片应单独覆盖。
- 动态统计另测零/常量、空组、mask、per-channel/grouped；不能拿 fixed-scale 校验冒充整个动态链通过。
- 非有限值若未定义或未验证，明确域限制；训练另测 autograd/STE，前向正确不等于训练正确。
- 回放真实层输入并接回原计算链；层片段通过后再决定是否做小样本整模验收。

### 完成的证据契约

- 每个候选保留源码／编译配置、模型与 shape 族、参考路径、数值误差和逐轮耗时；失败及回退也记录。
- 运行验收核对真实进程／退出信息、新鲜日志和本轮实测结果，确认源码与输入匹配。计时器触发、启动成功、进程结束、残留状态文件都不能单独证明完成。
- 局部算子用首尾 Event100；整模用 host 时钟，在边界等待相关设备。保留相同输入、预热和交错顺序，逐题响应与总耗时一起验。
- 明确哪些 shape／模型／数值域实际通过；编译成功、单 shape 胜出、单层加速都不能替代整模结果，也不能推断新模型自动正确或更快。

## 2026-10-19 真机教训：不是所有“简化”都会快

Ascend 910B2 / PyTorch 2.9 / Triton-Ascend 3.2.1，固定尺度 BF16 QDQ；以下是 Event 图执行微基准，其他机器需重测：

| 尝试 | 观察 | 决定 |
|---|---|---|
| tile 1024→4096，大张量 | HIF8 约 334→164 μs；E4M3 约 315→117 μs | 保留大 shape 候选，小 shape 另看 |
| 除以 2 的幂→乘精确倒数 | 穷举正确，但比已调 tile 略慢 | 回退，不因指令看着少就保留 |
| 小张量继续抠核 | 设备几 μs，普通 Python 调用约 130 μs | 先解决下发，不能许诺同倍数应用收益 |
| PyTorch `ldexp`→tensor 位操作 | 真实输入逐值相等，却更慢 | 后端实测优先于算子名称直觉 |

原始输入、脚本和完整表留在来源项目的 `docs/experiments/fakequant-fusion-event.probe.report.md`；可移植 skill 不依赖这些本机文件执行。该轮只覆盖有限值、连续布局、标量尺度前向。

同日分型接入（来源项目`docs/experiments/hif8-kernel-integration.report.md`）：
- 独立scalar/row/channel/expert/masked-row核，σ参数和逐行范围另核；保留原方差与专家归约
- GLM同8题host A/B/B/A：评分68.51→54.59s，eval102.71→88.43s，逐题响应一致
- 逐行核沿用标量核的4096 tile会UB溢出，改2048；按形态调参，以整模实得收益收口。训练与其他工作负载另验

## 收口与停止

- 正确性通过且端到端收益可重复：采用当前版本、记录配方，回算法主线；不把更高峰值当未完成项。
- 预算耗尽、收益只在噪声内，或下一步投入明显大于等待节省：停止，保留当前赢家或参考路径；不自动换热点继续优化。
- 整模等待已支持研究节奏时，采用可靠版本；单项kernel已验不要求继续爬坡。完整收口／重开规则见SKILL.md第10节，不因监控未满载自动换热点。
- 需要改变舍入、统计组或降低精度才能快：这是新算法对照，不能冒充执行优化。
- 不因“算法研发期”或“格式无原生支持”自动停止；不设通用百分比硬门槛，也不承诺 Agent 固定几小时完成。
