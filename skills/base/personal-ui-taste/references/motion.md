# 交互与动效：先做状态，再做动画

2026-10-26 重写（v4.0）。上一版把重点放在"克制"，导致该有反馈的地方也没有。这一版按**状态 → 转场 → 叙事**三层分工：工作界面必须每个状态都答得出来，展示页才可以编排。材质与阴影见 [material.md](material.md)。

## 一、先答状态，再谈动画

一个控件交付前，下表每一格都要能说出来；说不出来的格子就是没做完。

| 状态 | 必须发生什么 | 常见缺法 |
| --- | --- | --- |
| rest | 层级清楚，可点的地方看得出可点 | 静态卡片看不出能点 |
| hover | 只改亮度/底色/环，不改尺寸 | 靠放大抖动，或整块 `translateY` 却没影 |
| press（按下瞬间） | 90–120ms 内出现"压进去"：位移 ≤1px 或 scale ≥.985，材质变内影 | 只有 hover，按下去没反应 |
| focus-visible | 环宽 3–4px、offset 2px，跟随圆角 | `outline: none` 之后没有替代 |
| selected | 与 hover 不同：常驻底色/环/字重 | hover 和选中长得一样，移开就丢 |
| disabled | 降对比 + `not-allowed`，不靠 opacity 一刀切 | 只是变淡，仍可点 |
| loading | 宽度不变，文字换 spinner，重复提交被拦 | 按钮变宽、整页跳动 |
| error / empty | 就地说明 + 恢复路径 | 只有 toast，内容区仍是空白 |
| drag | 抓取时抬升一级海拔，落位有过渡 | 拖起来没有反馈 |

**按下比回弹快**：`active` 用 90–120ms，回到 rest 用 180–240ms。时间反过来就是"果冻"。

## 二、曲线与时长

```css
:root {
  --ease-out:     cubic-bezier(.22, 1, .36, 1);      /* 进入、展开、位移 */
  --ease-in-out:  cubic-bezier(.4, 0, .2, 1);        /* 对称位移、抽屉 */
  --ease-ios:     cubic-bezier(.28, .11, .32, 1);    /* 大位移、页面级过渡 */
  --ease-press:   cubic-bezier(.3, 0, .2, 1);        /* 按下 */
  --dur-press:    110ms;
  --dur-fast:     160ms;
  --dur-base:     220ms;
  --dur-slow:     320ms;
  --dur-page:     450ms;
}
```

| 场景 | 时长 | 曲线 |
| --- | --- | --- |
| 颜色、环、hover | 140–180ms | `--ease-standard` 或 ease |
| 按下 | 90–120ms | `--ease-press` |
| 浮层出现 | 160–200ms（位移 4–8px） | `--ease-out` |
| 浮层消失 | 100–140ms | `--ease-in`（关闭要比打开快） |
| 内容切换 | 180–240ms | `--ease-out` |
| 页面/路由转场 | 300–450ms | `--ease-ios` |
| 叙事入场 | 600–1000ms，分批 | `--ease-out` |

超过 400ms 的动画必须回答"用户在等什么"。答不出就砍。

需要真物理（拖拽回弹、底部抽屉甩动、图表指针跟随）时用弹簧，不要手调贝塞尔：

```css
/* 弹簧近似：先过冲一点再落定。参数感 = 硬度 170 / 阻尼 26 */
--ease-spring: linear(0, .009, .035, .078, .134, .199, .268, .336, .4,
  .456, .502, .538, .564, .581, .59, .592, .588, .58, .568, .553,
  .537, .52, .503, .487, .472, .459, .448, .439, .432, .427, .424, 1);
```

规则：弹簧只用于**被用户手势驱动**的运动（拖、甩、松手回位）。点击触发的界面转场用贝塞尔——过冲在"我点了一下"的场景里会显得失控。

## 三、三种动效语言

| 层 | 触发者 | 允许的动效 | 剂量 |
| --- | --- | --- | --- |
| 反馈 | 用户每一次操作 | 按下、hover、选中、保存提示、加载 | 必须全有，不可省 |
| 转场 | 视图/上下文改变 | 共享元素、内容切换、抽屉、路由 | 每个交互一个，不多层叠加 |
| 叙事 | 用户滚动或进入页面 | 分批揭示、固定示意 + 步骤联动、媒体入场 | 一页一个主段，其余安静 |

工作台不是"只能有 160ms 反馈"，而是**反馈层必须齐、叙事层要克制**。阅读/展示页可以用滚动章节，但静态可读性不能依赖动画播放完成。

## 四、现代能力：优先用平台

这些在 2026 年的基线浏览器里可直接用。先查项目目标，再决定要不要 polyfill。

| 能力 | 用来替代 | 剂量 |
| --- | --- | --- |
| `transition-behavior: allow-discrete` + `@starting-style` | JS 开门才能播的浮层动画 | 浮层、toast、dialog 标准做法 |
| `animation-timeline: view()` / `scroll()` | IntersectionObserver + class 切换 | 一次一个元素组；不做滚动劫持 |
| View Transitions API（含 `view-transition-name`） | 手写 FLIP 共享元素 | 同文档内转场；跨文档需同源配置 |
| `popover` + anchor positioning | 手写定位与点击外部关闭 | 菜单/tooltip 优先 |
| `:has()` | JS 维护父级状态类 | 表单组、卡片选中态 |
| `@container` | 靠视口断点的组件布局 | 侧栏内嵌组件 |
| `linear()` | 弹簧曲线 | 见上 |

统一要求：**原生能做就不引库**。需要复杂时间线（多场景、音画同步）再读 `huashu-design` 的 `animation-best-practices.md`；需要滚动叙事配方读 `design-taste-frontend` 的 `references/motion.md`。引库前先算清体积与降级路径。

## 五、性能与降级

- 只动 `transform` / `opacity` / `filter`。动 `width/height/top/left` 会让整段布局重算，列表里尤其明显。
- `will-change` 只在动画开始前加、结束后删；常驻会让图层爆炸。
- 一屏同时运行的动画 ≤ 3 组；列表 stagger 每组 ≤ 8 项，其余直接到位。
- `backdrop-filter` 与滚动容器不要同层：滚动时每帧重新合成。
- `prefers-reduced-motion: reduce` 时：取消位移、缩放、揭示，**保留颜色/环/材质变化**——反馈不能一起删掉。
- 动画失败不能留白：揭示动画依赖 JS 时，用 `@media (scripting: none)` 或默认可见 + `animation` 覆盖，别让正文等一个可能不跑的 observer。

## 六、反例

| 症状 | 为什么错 | 改成 |
| --- | --- | --- |
| 每块都 fade-and-rise | 满页同一种入场，等于没有节奏 | 一个主段落做，其余静态 |
| 每个卡片 hover 抬升 | 静态卡片被伪装成按钮 | 只有真能点的抬，且配环 |
| bounce / elastic 缓动 | 界面不是玩具 | `--ease-out` |
| 无限循环的脉冲点、滚动数字 | 假装有进度 | 真实状态文字 |
| 滚动劫持、整屏吸附 | 夺走滚动控制权 | 自然滚动 + sticky |
| hover 触发浮层无延迟 | 鼠标划过一路弹窗 | hover 意图延迟 80–120ms，移出立即关 |
| 只 `scale(.9)` 当按下 | 果冻，且没有材质变化 | 位移 1px + 内影（见 material.md） |
| 关闭动画比打开还慢 | 等待感 | 关闭 100–140ms |
| `outline: none` | 键盘用户失去落点 | `:focus-visible` 环 |

## 八、验收

真实点击后逐条过：

1. 每个状态都能用键盘到达；`Tab` 顺序与视觉顺序一致。
2. 按下 100ms 内出现反馈；松开后 240ms 内回到静止。
3. 结果先于动画出现：数据已更新，动画只是解释它。
4. 关闭比打开快；重复开关不叠影。
5. 减少动态效果下仍能完成全部操作。
6. 连续操作 10 次不掉帧（Performance 面板看长任务）。

截图看静态构图，录屏看节奏；两者都不等于用户已认可最终观感。
